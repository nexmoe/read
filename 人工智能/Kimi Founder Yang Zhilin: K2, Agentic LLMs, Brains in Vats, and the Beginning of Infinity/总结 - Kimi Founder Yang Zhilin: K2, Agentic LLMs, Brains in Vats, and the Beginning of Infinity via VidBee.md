**整体判断**
AI 仍在爬一座没有顶的雪山：问题不可避免，但可以被解决；解决一个问题会抬高知识边界，并带来新问题。AGI 是方向，不是某一级台阶或某个可宣布“到达”的终点（不同于登月）。技术会持续提升，对社会的消化则要几十年甚至更久，类似蒸汽机之后的社会重构。AI 是人类文明的放大器，也可能是突破知识边界的下一个巨大杠杆。

**过去一年的范式变化**
- **长思考推理（以 o1 为代表）**：模型在推理中反复“提出猜想—自我验证”，等价于多次尝试，把一次作答变成可扩展的思考。它仍是“缸中之脑”，不与外界交互。
- **Agent 强化学习**：多轮调用搜索、浏览器、代码等工具，下一步取决于环境反馈。这是另一种 test-time scaling：拉长轮次或拉长每轮思考 token，从而端到端完成耗时数小时、无需人工介入的复杂任务。
- **一方产品**：模型公司先设计工具与 context，再在该环境里正向训练，模型与工具天然匹配，上限可能高于在闭源模型上做脚手架、逆向拟合训练分布。两种路线会长期并存，边界尚未清楚。

**对 L1–L5 的理解**
Chatbot、Reasoner、Agent、Innovator、Organizer 是重要里程碑，但不是严格串行。多轮交互与纯思考是两个不同的 scaling 维度；Claude 更押 Agent，推理分数不必最高也能做出很强的 Agent。要做到最好的 Agent，最终仍需要很强的推理。Innovation 的关键是模型能否参与下一代模型研发（如用 K2 做 K3）；Organization 是把单 Agent 扩成可分叉、并行、合并的 Multi-Agent，两者可以并行发生。甚至可能要用 L4（用 AI 训练/对齐 AI）去解决 L3 的泛化，顺序可以倒过来。这些能力都会持续变强，推理上限今天也说不清。

**公司这一年的关键转向**
研发重心从“预训练 + SFT”转到“预训练 + 强化学习”，并需要相应的人才与研发方式；产品形态从对话转到 Agent。

**K1.5 与 K2**
- **K1.5**：验证强化学习路线。早期并不明确的结论是：不必 heavy 依赖 process reward 或 value function，端到端 reward 就能训得很好，过程中还积累了 RL 基建与算法。
- **K2 要解决 token efficiency，而不只是训得更快。** 高质量文本增长慢，多模态数据又抬不了文本智商，数据接近常数；compute efficiency 只缩短时间，不提高智能上限。Muon（矩阵正交化优化器，在 Keller 方案上做大规模适配）在 compute-optimal 实验中约有 2 倍 token 效率，相当于同样数据吸收更多智能；Adam 用了约十年，但未建模参数间依赖。大规模才出现 Max Logit 爆炸，小规模复现不了，他们用 clipping 等方式稳住训练。同时对稀缺高质量数据做改写以减轻重复学习的过拟合；改写是否产生新知识，取决于有没有新的信息输入，此事仍有很大探索空间。更大稀疏度、更多参数也会提高 token efficiency。
- **K2 的另一目标是可泛化的 Agent 能力。** 当前 RL 的训练任务和指标往往是单点的：刷高某个 benchmark 不等于泛化变好，Agent 训练里过拟合工具、环境和任务比对话模型更严重。公开 benchmark 少且片面，评估本身是瓶颈。可能的出路是让模型更多参与训练与对齐，而不只优化单点任务。
- K2 立项依赖更早的技术积累（约一年前开始研究，如 Muon 需多级 scaling 才暴露问题），按下训练按钮到结束并不长，前置研发才长。研究与训练是同一团队。除 Max Logit 外，其余问题多在小规模验证后可迁移。具体 know-how 写在技术报告里。

**如何定义 Agent**
Agent 的核心是多轮 + 工具：多轮用来做 test-time scaling，工具把“脑”接到互联网和可用代码描述的数字世界。缺的是对没见过的长尾、定制工具（内部库、文档、专有 API）的泛化；通用 Agent 若能泛化，很多垂直 Agent 就只需换工具，不必另做模型。设计目的是通用（universal constructor），不是模拟人；与人类工作方式相似只是结果，如同飞机的目的是交通而不是像鸟。

泛化仍受分布限制：RL 比 SFT 好（on-policy 采样、负梯度），但在一类数学竞赛上做到极高分，并不自动让其他数学题达到同样水平，仍是“种瓜得瓜”。要摆脱这一点，需要更多由 AI 参与的数据与训练；泛化会变好，但未必有尽头。

好的环境应正向设计、足够通用，而不是为少数任务定制后再逆向拟合某个模型。任务不宜一上来就极难（采样效率极低、算力浪费）；搭配采样策略的 RL 更像隐式课程学习，从中等难度逐渐加难。今天很多任务仍来自人类存量或人工设计，AI-native 成分少，这会伤害泛化。Coding 是重要子集：好验证、代表数字世界的自动化，也能用来制造新工具和做 context engineering，但只做 Coding Agent 不够；非程序员用它做事，靠的就是一定泛化。

**Agent 还缺什么**
高频工具还不够好；长尾、完全 OOD 工具的泛化不够；缺少能真实反映体验、且尚未饱和的 benchmark。长期更看重用 innovation 层技术去抬 Agent。Long context 同样关键：很多任务 128K、256K 不够，需要百万级甚至更长，同时智商不能掉。这要求极高压缩率、足够大的模型，并在架构上平衡长短上下文——有的架构长上下文变好、短上下文变差。复杂 Multi-Agent 也不能只靠端到端 reward，中间 workflow 能否少依赖人工设计仍是挑战。

**开源与市场**
原判断大体仍在：社区能改进推理、带来使用，但把 base model 本身变得更好，目前仍主要靠原厂。基于开源模型做 agentic post-training，可以做出场景很强的专用 Agent，并赋能下游，但很难再折回提升主 base model。他们希望长期、选择性开放技术和 know-how，以合作和生态一起爬山，但不是全部开源；这既是技术选择，也有市场博弈。过去两年模型市场从很多家收敛到少数几家，是大概率趋势。中国公司开源并不普遍，其中有竞争因素，但对社区互借、加速技术是好事。

**有概率的非共识**
一是 Agent 泛化，以及能否在其上做出新东西；二是在超大规模上用非 Adam、基于矩阵正交化的优化器。做出之前这不是共识，但它显著提高 token efficiency，使后面的 post-training 有更高上限可榨。

**AI 时代的产品与系统**
“模型即产品”没有变：训练时就必须把模型、工具、context 配好，训完后产品主体已完成，交互多半是最后一层。通用性让系统概念上更简单（一个模型，少路由），工程上更难：不同任务、工具定义、数据 pattern 会打架；多模态不能损伤文本智商，而要激发同一个“脑子”，不能让一部分 expert 专做多模态、变成“傻的多模态”。越到 post-training 和 RL，这种冲突比预训练更严重。

交互随能力变：Copilot、Cursor、Claude Code 每一代都不同；模型再强，今天的编程 Agent 交互也不是终局。新系统会跑在数据中心里的 “AI factory”，终端有的可复用，也会出现新交互。

数据墙是事实，突破方式是提高 token efficiency，并把更多算力 scale 到各类 RL。模型变好的速度目前没有放缓，甚至在加快。数据飞轮还不强，一是因为 on-policy、带负梯度的 RL scaling 效率远高于预训练，算力提升显得其他信号很小；二是外部反馈噪声大，大模型对噪声敏感，不像推荐系统。飞轮要成立，需要在模型能力范围内设计能降低噪声的新交互。用户反馈不宜直接拿去训练，但足够的用量能看见需求分布、好坏场景，再抽象成评估；Agent 类专业用户已能产生真实商业价值，闲聊则未必。

**商业与定位**
明确路径是 API 和一方产品，两者都会试，但首要仍是把模型做得更好。市场已被验证且增长很快；能否赚钱取决于效果。若接近或超过 Opus 一类水平，空间会更大。K2 受关注不改变“漫长旅程”的判断：持续做下一代，不断解决新问题。

他们不把自己定义成“中国的 OpenAI”，中美不同，要放在全球视角；想做的是持续爬山、与时间做朋友。

**研发决策与下一步**
技术战略——下一步做什么、不做什么——大约决定公司五到六成走向。好决策靠实验证据，不能拍脑袋。较早且有效的押注包括：较快做 long CoT、Muon、更大规模训练，以及较早做开放的 Agent 模型。K2 更接近一个 base，post-training 算力还能加很多，上限应明显高于现在；下一代 base 会再提升。多模态会做，但多模态能力本身要强，且必须是“聪明的多模态”。当前最重要的未解问题是 Agent 泛化：避免 RL 只拟合有限 benchmark、在观测不到的任务上大幅变差；同时在高智商下继续加长 context。Linear Attention 等架构有 bias，可能伤智商，但是可逐步解决的问题。

**模型公司与 Agent 公司的边界**
一方产品的优势是垂直整合，模型在自家工具环境里训练，不必逆向工程。Agent 空间太大，一方做不完：若工具需要大量领域 know-how、评估是一方覆盖不到的，或掌握别人做不出的入口（如线下服务成交），专用 Agent 仍有窗口。也可以不训模型，只把垂直工具做到极好；工具若太通用，就会与一方产品重叠，此时垂直整合更强。通用 Agent 的流量和商业模式成熟后，专有工具会因为更高商业化效率而愿意接入，内容平台也有可能如此，但这需要很长时间。Manus 这类公司现在更像客户/合作大于竞争，但产品和关系会演进，类似 Claude 与 Cursor，最终取决于对方能否做出别人做不到的模型能力或工具环境。目前一方整合优势是存在的。

**关于 K2、预测与智能来源**
K2 这个名字对应“最难攀登的山峰之一”，不是最高峰，也不是终点；从对话到 Agent、base 继续变大，本身就难。结果大体在预期内：训练周期长、成本高，能预测的都应提前预测，因此 scale 成功率较高；唯一没预测到的是小规模上看不见的 Max Logit 问题。

仅靠 next-token prediction，模型变大后知识、对话、情商会变强，但推理尤其数学未必单调变好，可能跳步；要靠 RL scaling 把推理范式激活、把知识解锁出来。更大的 base 仍会抬高 RL 上限。世界模型可理解为用 AI 模拟世界、再用 AI 训练 AI，是通往更好泛化的一种可能。此前对更远代模型的想象里，已有一部分实现，例如持续数小时完成任务；接下来相对明确的是见到更多 variation、继续突破泛化，但评估与世界模型怎么做仍要实验。

**组织、CEO 与心态**
创造知识不像纯经验主义：经验本身不直接给知识，科研是提出猜想再设计实验验证，这个过程很像强化学习。管团队也类似：SFT 是手把手规定做法，太多会扼杀能动性；RL 是给目标和奖励。应以 RL 为主，用少量 SFT 当先验，防止飘太远或遗忘，但奖励极难定义。若只奖励把 benchmark 刷高，会被 hack 和 overfit，分数上去模型却没变好。RL 管理的风险是 reward hacking，SFT 管理的风险是失去创造力。CEO 要掌握的就是这三者的平衡。

高低点都有，但心态是做时间的朋友：喜欢这件事，就专注把它做好。创业中的困难大体可预料，真正无法预测、也最有意思的是新的技术问题如何出现、如何被解决。做 AI 是因为问题重要，且探索本身有意思。风险不能否认，对齐和社会机制都要做；放弃 AI 等于放弃文明上限。人的体验和情感难以被替代，创造可能大量交给 AI，人可以在好的分配机制下享受产出；机制调整是一二十年的慢过程，不是一两年完成。

相对一年前，只要还在往上爬，成功概率就在变大，因为有人会停。恐惧会有，但更该看当前这一步能做什么。弯路一定有，包括技术和业务决策；知识、公司都是动态的，某一阶段正确的东西之后会错，重要的是发现后调整。相对不变的是人才与技术积累，其余要随反馈和环境改。中间状态总会受时代局限、成为被批评的对象。

和互联网产品不同：技术快速变化时，投流很难打赢，最多是辅助；配比要看 PMF 和商业化进展，并动态调整。今天最大的变量仍是智能。决策上尽量避免情绪化。过去一年心态上最大的变化，是接受问题会一直存在，持续解决新问题既最重要也最有意思。兴奋程度大致稳定：一方面更适应，一方面 AI 进展很快。
