先说结论。这座雪山很可能没有顶。**AGI 不是某一级台阶，而是一个方向。** 技术上只有两句值得刻在石头上的话：问题不可避免，问题可以被解决。每解决一个，就再往上爬一段；爬到后来，往上走的甚至不一定还是人，而是 AI 自己。再远一点看，下一个突破知识边界的杠杆就是 AI，它是人类文明的放大器。风险不能说没有，但不能为了躲开风险，先把文明的上限放弃掉。

## 一年之后，四下还是雪

创业第一年结束时，标题是「向延绵而未知的雪山前进」。又过了一年，站在二〇二五年七月，那种感觉并没有换掉。AI 一天，人间一年，AI 的一年折算成人间是多少天，不好说。很多东西确实变了，可雪山还在，只是往山顶又走了一段。

模型的进步很大。两年前写一篇文章都写不明白，现在不但能写好文章，还能连续工作几个小时，做完一件很复杂的代码任务。这在两年前很难想象。爬山的过程里，一些新场景被解锁了，中间这条路大概长什么样，也比以前清楚。但路上看到的景象差不多：再往上，仍然有很多未知的技术问题要解决。

所以是更清晰，也还是会迷惘。四下都是雪。很多东西变清楚了——两年前，强化学习该怎么做、模型怎样才有更强的推理和 agentic 能力，并没有那么清楚，当时更在意的是预训练能不能做好，再加上 RLHF，把对话体验做好。现在有些新问题有了答案，这些答案又展开成别的问题。你可以做强化学习，可强化学习最终还是依赖好的评估和验证。做数学题，或做有测试用例的编程，可以做得比较好；换成更复杂的端到端任务，评估和衡量往往并不容易找到。

## 两句要刻在石头上的话

最近反复在看 *The Beginning of Infinity*，看了好几遍。里面最重要的是两句要刻在石头上的话。第一句：**问题是不可避免的。** 第二句：**问题是可以被解决的。**

启蒙运动之前，社会是静态的。大家并不追求创新，会用很多神奇、但并不是好的解释去说明看到的现象。天上打雷，就说有雷公；冬天下雪，就说某位神心情不好。真正做科学研究、创造知识的人极少，整个结构是静的。启蒙之后，社会变成动态的。新知识不断被创造出来：一个知识解决一个问题，解决的时候又产生新问题。知识边界在拓展，新问题就会不断出现。

研发 AI 恰好是这样一个过程。强化学习的很多问题解决了，马上面对评估、衡量、验证这些新问题，需要新的答案。这也是有意思的地方：永远有新问题可以解决，每解决一个，技术就再攀登几百米。也许有一天会发现，这座雪山可能没有尽头。希望它一直没有尽头。Beginning of infinity 就是这个意思：它可能是一座无限的山，人一直往上爬；爬到一段时间之后，甚至不一定是自己在爬，而是用 AI 来爬。

现在已经会用 K2 做很多模型训练和数据处理。这些事以前要人工写代码，有的同学不会写，就做不了。现在不少数据处理、模型分析，甚至一部分训练，可以慢慢交给模型。模型成了放大器，用来更好地攀登这座山。问题会持续产生，然后持续被解决，再发现新的问题。

山如果无尽，追求的是攀登本身，是一直越爬越高。原来在山底下，再往上一点，看到的景色就不一样。这是一个动态进化的过程。想追求的就是越爬越高。

## AGI 不是某一级台阶

以前会固化地认为，终点就是 AGI。今天的终点已经不是「到达 AGI」了。AGI 可能是个方向，不是某一级台阶——不是爬到某一级，就突然一夜之间拿到 AGI，可以喊一句「此时此刻我们实现了 AGI」。公司用登月来命名，但 AGI 和登月有一个区别：登月是站上月球那一刻就有终点，你可以号称达到了；AGI 不是这样。

这里有两层。一层是技术一直在提升。很多领域里，模型已经可以做得比百分之九十九的人更好，不妨就把它看成已经是一种 AI。很多数学题、编程竞赛题，按现在的速度，可以预想很快会被充分解决。但很难说某一个时间点，突然就能盖章。

另一层是，技术对人类社会的影响是更长周期的事，你也可以把它看成 AGI 的一部分。有点像蒸汽机出现之后，整个社会要花几十年、几百年去消化。有些工作不再必要，又会产生新的工作、新的方式。人会用 AI 做更多事，每个人都可以成为超人。社会的工作方式和运行效率都会发生很大变化。

## 这一年，范式换了两条，外加一条产品路线

过去一年，全球大模型里最重要的变化，至少有几件。

一件是基于长思考的推理模型，和相应的强化学习。o1 是第一个做出来的代表。本质上，它让模型在过程中做很多尝试和反思。反思是重点，里面其实是两种能力：不断提出新的猜想，再对猜想做自我验证——这个猜想到底对还是错。你并没有显式训练一个验证模型，但推理过程里隐式地做了验证。可以理解成：它把问题做了很多次，每次都是猜想、验证、再猜想、再验证，最后得到答案。

能力因此大幅提升，是因为你本来只能做一次：直接给一个答案，对或错，没有这个过程。现在可以不断提出猜想再验证，等价于尝试了好几次，**可以把 pass@k 变成 pass@1。** 这和人做科研、解题很像，都是不断提出新猜想再验证。它是自由探索，不是一条死直线；可如果先不考虑并行采样、只做串行采样，它又确实有线性的一面：每一次新猜想，都基于你已经否定过的猜想。你也可以把这条线性过程和并行策略搭配起来，同时采样很多条。最近也有论文说，串行的上限可能更高，这和我们的一些实验结论有关。这是一种范式。

但它还是一个**缸中之脑**。想象一个鱼缸，把一个脑子放进去，它和外界没有联系。它只在自己的大脑里想，一直想，不需要和外界产生任何交互，就能解一道题。

另一件很重要的范式，是基于多轮 Agent 的强化学习，或者说用强化学习训练出能做 Agent 的模型。它的特点是会和外界做很多交互：边思考边操作，做很多轮，一会儿调用搜索，一会儿用浏览器，一会儿写几行代码，用多轮把问题解决掉。它不再是缸中之脑。下一步行为，取决于交互之后外界给的反馈，取决于外界给的新状态。

这两件事指向同一个东西：**test-time scaling**。你可以在测试、在推理的时候做更好的规模化。以前做 chat、做对话，更多是单轮输出一个结果。让它写一篇文章，它写一篇；再让它润色，它再输出几百个 token。token 数量很少。无论是基于长思考的强化学习，还是 Agent 强化学习，本质上都是在规模化推理时的 token：要么把轮数打得更多，要么在每一轮里放进更多思考 token。token 规模上去，就能完成更复杂的任务，完成时间也会更长。现在可能花几个小时做一件很复杂的事，过程中不需要人参与。比如把一个代码仓库克隆下来，翻译成另一种语言，调试、测试、修掉所有 bug，让它正常运行。这样的工作可以端到端直接完成。这就是测试时规模化的两种表现。

还有一个很有意思的趋势：更多模型公司在做一方的 Agent 产品。一开始，如果从半年前或去年看，很多产品是在基础模型上做脚手架，设计一些工具，让模型更好用，搭出一个产品，享受模型一出来的能力。这件事本质上是在**逆向工程模型的训练过程**。模型是在各种内部环境、工具和脚手架里训练出来的，这些并没有直接开放给你。你要立项，就要更接近它的分布：到底用什么工具效果好，用什么样的 system prompt 效果好，用什么样的 context engineering 效果好。这是一个逆向过程。

模型公司做一方产品，逻辑完全不一样。你不再需要逆向，而是正向：先把工具设计好，把 context engineering 的方法设计好，再在这个环境里训练模型。模型天然就会在你的环境里表现更好。两种思路里，第二种的上限也许更高，因为你可以更好地把工具和模型整合在一起。模型有些地方解决不好，你可以改工具的设计，同时端到端训练。这在开发方式上是一个比较大的变量。

说得更直白一点：第一种脚手架，像 Manus 那种方式；第二种，是 Claude Code、ChatGPT Agent 这样的一方产品。我们自己在一方产品上的投入还不算特别多，主线仍然是模型。后面就看这两种东西怎么配合，在生态里各自是什么样，边界分别在哪里。

## L1 到 L5，不是必须排队上车

ChatGPT 设了 L1 到 L5：Chatbot、Reasoner、Agent，后面是 Innovator 和 Organizer。这里的逻辑，表面上是能力一步一步依赖。实际看起来，Agent 的上限取决于你有很强的 reasoning，但并不是说你必须先把狭义的长思维链推理做完，才能做 Agent。把技术发展的顺序换一下，假设先做出 Agent 能力，再去做现在这种 long CoT 的 reasoning，其实也成立。

Claude 的路线就是赌在这一点上：reasoning 上做得并不是那么多，但 Agent 可以做得非常好。背后是两种不同的 test-time scaling。一种靠多轮，因为要和外界交互、多次使用工具，缩放的是轮次。另一种几乎没有交互，只是一直在纯粹地思考。Claude 很多模型的 reasoning 成绩并不是非常高，Agent 的峰值却很高。两者并不一定是依赖关系。可如果你想做最好的 Agent、让它解决最复杂的任务，最终还是需要 reasoning 也很强。研发顺序不是必然的；要达到一个东西的最好，需要把另一个也做到最好。想把 Agent 做到最好，就要把 reasoning 也做到最好。

一种理解是：Reasoner 是 Agent 的前提，因为语言要通过推理，才能在 Agent 里泛化。方向上可以这么看——要解决最复杂的 Agent 问题，不会推理会很难。但就算没有这种推理范式，你仍然可以在一定程度上做一些不那么需要推理的 Agent 任务，不必在思考过程中说出几千个 token，来推理当前到底该怎么做。你可以通过多轮交互，从环境里得到反馈：写一些测试，跑这些测试，也能解决一些相对复杂的任务。这就是为什么现在会看到，Claude 在有些场景里做得更好。背后是不同的技术 bet。最终绕不开的是：再往山顶爬几步，两个都要，只是时间问题。Innovation 和 Organization 也一样。不同的技术底子会让短期路径略有区别，而这些区别会有影响，因为你面对的是一个动态的市场。

有了 Agent 之后，为什么下一档是 innovation？最关键的一点是：**模型什么时候能参与模型自己的开发。** 我们希望 K2 能参与 K3 的开发。没有 agentic 能力，这事很难做。有了之后，它可以提出新想法，做对应实验，分析实验结果，得到结论，再迭代下一版想法，或者优化某一处 infra 的性能。这都需要很强的 agentic 能力。Innovation 真正大的发生点，至少有一个很关键的观察窗口：模型什么时候能进入自身研发、自我迭代。

Organization 和它也不一定完全线性，有些东西是并行的。现在已经看得到趋势：有了一个 Agent，就可以扩成 multi-agent。从一个 Agent fork 出很多不同的 Agent，做不同的事，串行或并行，再合并，再拆成不同任务。有的写测试，有的写文档，有的设计整体软件框架，可以有分工。两个会一起发生，并不奇怪。Reasoning 加上 Agent，更像是 innovation 和 organization 的前提。

Innovation 的标志，是模型的自我迭代。Organization 可以比较简单地理解成一个 multi-agent 系统，从现在的 Agent 长出来。已经有很多雏形。挑战在于：multi-agent 怎么端到端训练，怎么不要过拟合到某几种 Agent 类型上，让它有更好的泛化。

这些级别是雪山的峰顶吗？也不是。可能真的没有顶。推理、Agent 这些能力都会随时间持续变好。推理能力的上限在哪里，今天不好说。它看起来像是 L2，可要真正做到很强很强的推理，空间仍然很大。L1 到 L5 更适合当成几个重要的技术里程碑，而且并不完全是串行项目。不会是一件事马上被解决，再去解下一件；它们会同时提升。你要解决开放问题，或者提出新的模型架构，推理能力又会需要更高的要求。这几项能力都要持续提升。

## 关键决策：预训练还在，重点换成了强化学习

二〇二三到二〇二四的关键决策，是二月决定创业，然后融资、组团队，下半年 Kimi 上线，并发布了长文本。二〇二四到二〇二五，技术上很重要的一次转向，是从以预训练和 SFT 为重点，转到以预训练和强化学习为重点。这需要做很多人才储备，也要改变研发方式。另一件是从对话到 Agent，它会很影响实际的工作方式。这两件是方向上的变化。

## K1.5 是把强化学习验证清楚

过去半年推出了 K1.5 和 K2。K1.5 更多是强化学习这条技术路线的验证，也是在追 o1，而且算比较早投入的。当时发现，你可能不太需要太多 process reward，或者 value function；这些东西甚至在训练过程中还有副作用。直接用端到端的 reward，就可以把模型训得很好。这一点在早期其实并不非常明确。这个过程里，也积累了强化学习的基建和一些算法上的 know-how。

## K2 想要的，是一个吃数据吃得更狠的底座

K2 的主要点有几个。第一，希望它是一个非常好的基础模型，一个非常好的 base model。那就得看整个领域预训练的瓶颈在哪里。高质量数据的增长确实很缓慢，多模态数据又没有办法很好地提升文本本身的智商。高质量数据有点接近一个常数。所以希望把每一份数据最大化地使用，也就是 **token efficiency**：同样吃下一样多的数据，脑子要长得更多，得到更多智能。

这和以前有些思路不一样。假设你在训练系统里做很多性能优化，让它训得更快，这很有价值，但训得更快本身不能提升智能上限。token 还是只有这么多，训得更快，只是在更短时间里完成训练，模型效果不一定更好。那是训练效率，或者说 compute efficiency，以前就有人在做。我们现在更多希望提升 token efficiency，把一份数据当成好几份来用。

所以很关注 Muon 这类优化器。它对 token efficiency 的提升比较大。Adam 这样的优化器可能已经用了十年，大部分模型都用 Adam 训练，但它的 token efficiency 并不够好，并不是把每个元素独立地考虑。对一个矩阵的参数，Muon 会考虑它们之间的依赖，学习效率更好。同样一份数据，能得到更多智能。早期实验里，在 compute optimal 的情况下，基本上有大约两倍的提升：你学一份数据，等于别人用 Adam 学两份。假设你有 30T 的高质量 token，等价于你现在有 60T，数据还是那么多，但学完之后脑子涨得更快。因为优化器更好，学习效率高了，吸收得更快。问进去一样多的数据，它吸收得更好，压缩率涨得更快，loss 降得更快。

Muon 是 Keller 提出来的。我们在上面做了很多优化，让它能在很大规模的语言模型上适配和训练。先前已经有工作，第一次让它在有一定规模的语言模型上训练；后来进一步规模化，又发现很多新的坑。比如 Max Logit 会爆炸。这在小规模实验上很难看到，大规模上会遇到。于是提出一些新的 clipping 方式去解它，让它在非常大规模的情况下仍然能很好地训练。token 有限，每一份都要产生更大的价值。

[配图：论文里的 Max Logit 曲线——小规模上看不到，规模拉大后数值异常冲高]

数据上也会做很多 rephrase。30T token 里面，真正高质量的可能更少，也许是几十 B 或几百 B。希望这些数据被很好地使用，所以做了改写，让模型更好地吸收，也有更好的泛化。同一份数据学很多次，泛化不一定好，会有过拟合。改写就是为了带来一定程度的泛化。具体改写方式可以有非常多种，我们找到一种在实验里效果比较好的，但这个空间很大，值得做非常多研究。

有一种观点说：改写和扩充其实没用。能写出来的知识，说明知识本身就在里面，没有新知识，除非改写时用了别的方法。这是个好问题，而且确实跟改写方式有关。理论上就看你有没有新的熵的输入。所以改写方式是有要求的。今天用的也不一定是最好的改写方式，这里还有很多可以探索的空间。

回到 K2：一方面希望它成为好的 base model，于是很希望提升 token efficiency。对应的设计还包括用更大的稀疏度加进更多参数，token efficiency 也会更高。参数多了之后，虽然学一样多的数据，吸收会更好。实验可以验证，它确实有更好的 token efficiency。

## 泛化，是现在 Agent 最大的挑战

第二，希望它有好的 agentic 能力。强化学习，以及对工具和环境的模拟，要让它有比较好的泛化。对一个 agentic 模型来说，现在最大的挑战其实是泛化。现在 RL 技术的局限在于：不管训练任务还是评价指标，很多时候都是单点的。你训 SWE-bench，它就提升 SWE-bench，这基本上是很确定的事。指标上去，并不意味着泛化变好。

所以也在尝试解决一部分泛化问题。不希望它过拟合到某些工具、某些环境，或某些具体任务上。这些任务可以是很好的观测，但不希望过拟合它们。这个问题在 Agent 训练里更加严重。相比以前的对话模型，泛化是一个更大的挑战。

这些能力为什么不放进预训练？这也是接下来想探索的。更多 Agent 能力有可能在预训练阶段获得。能不能因此提高泛化，取决于做法：数据分布是不是足够广，有没有很好的方法去评估。现在整体评估仍然是瓶颈，它阻碍 Agent 模型变得更加泛化。能用的 Agent benchmark 不是非常多；那些 benchmark 上的一个分数，很多时候并不是对能力的完整反映，比较片面。这是大家要想办法解决的问题。

一种潜在思路，是用更 AI-native 的方式训练 AI，让模型参与更多训练过程。如果 AI 能做很好的 alignment research、做很好的对齐研究，理论上它会有更好的泛化，而不仅仅是在优化一些单点任务。这是 Agent 下一步非常重要的一点。它今天可能还不像对话那样有这么好的泛化。这可能会是雪山上接下来的几百级台阶。

整体上，我们仍然借鉴了很多技术方向，但也希望有自己的创新。至少在公开能看到的资料里，我们是第一个用这种非 Adam、基于矩阵正交化的新优化器，在这么大规模的模型上训练，这是一个创新点。一些 Agent 数据的做法，在公开可查的资料里也做得比较早。这个空间会越来越大。有意思的是，越往上爬，你会发现空间在变大。完成同一个任务的 token 在变多，问题的复杂度在变高。就像前面说的，问题不可避免，但问题总可以被解决。不可避免的问题看起来比以前更多，研究空间可能更大。这是现在比较直观的感受。

## 按下训练按钮之前，周期其实很长

K2 筹备了比较长的时间。这里很多技术，从去年就开始一个一个研究。像 MuonClip 这样的技术，需要比较长的周期。一开始做非常早期的实验，发现想法好像有潜力，用小实验验证潜力到底有多大。从有这个想法，到最后放进一个万亿模型里训练，要经过很长周期，通过不同规模的 scaling 实验验证有效性。有些问题只有 scale 到一定规模才会发现。如果只看模型本身，从按下训练按钮到结束，时间倒没有那么长；整体研发必须更前置地做很多事，才能保证训练比较顺利。

Agent 这条 bet 什么时候开始，也要做很多积累。不同时间点的做法不一样。一开始不一定非常端到端，而是积累一些环境和数据；到后面可以更端到端地做强化学习。中间需要很多基建和数据。这个积累很难说一两个月就做得非常好。大模型和相关技术挺需要时间积累，还是要做时间的朋友。技术曲线有点陡峭，不是今天想做，就能把它做出来。

所以立项可以分成两段。大约一年前开始积累各种技术。至于 K2 这个模型本身，是最近几个月决定去训一个这样的模型，并把哪些技术用上。不是今天想训，再从零去搞很多东西——那样就不是两三个月能解决的。立这个项也很正常，因为一直在训练下一代模型。决策无非是：下一代到底要加入哪些技术，期待它是一个什么样的模型。K2 之后的下一代长什么样，现在也在考虑。这是持续要思考的决策。每次都是看工具箱里多了哪些新东西，到底把哪些拿出来用。

做研究和做训练的是不是两个团队？其实是一个团队。这些东西很难分开。实际训练过程中会遇到问题，如果之前都不了解，就没有办法解决。

开训过程中遇到的挑战，是雾：一训，它就会炸。论文里画了图。Max Logit 会长得非常高，这对训练稳定性有影响。训久了，很多指标会不正常，对模型上限有害。于是回过头重新看这个问题，再修它。小规模实验预测不了，大规模上的爆炸在小规模里复现不出来，小规模根本不会炸。其他方面基本还好，因为都在小规模上做了很多实验，也基本可以迁移。唯一这个，小规模验证不了，就要在 scale 过程中再解决。

训练过程中最重要的几个 know-how，都写在论文里了。我们比较开放，主要都在技术报告里面，还是想跟社区分享更多。

## Agent 的两个特征：多轮，和工具

怎么定义 Agent？它是从缸中之脑，变成可以跟世界交互。所谓 Agent，最重要的特征就是可以多轮地使用工具。两个词：一个是多轮，一个是工具。多轮是你能做很多次，这是一种 test-time scaling。工具是连接这个脑和外部世界的方式。用搜索引擎，就可以把模型和整个互联网连起来。可以写代码，就可以把脑和数字世界连起来——数字世界里的自动化，基本上都可以用代码描述，于是它拥有自动化的能力。

接下来会有越来越多的工具，而且会有一个长尾分布。模型如果泛化得好，就不只使用常见工具，还可以使用非常个性化的工具。比如一个非常具体的问题：让模型访问公司内部的数据库，或个人的一些文档，甚至访问定制 API，完成某些业务操作，退票，或者下一笔订单。它应该能泛化到没见过的工具上。

Agent 现在最缺的，其实就是这种泛化。泛化更好之后，以前大家讨论的各种垂直 Agent，就不一定非常需要了。通用 Agent 能泛化到常规工具上，很多领域专有的问题就可以直接用这些工具解决。每次只是给它加不同的工具：定制的数据库、定制的 API、定制的文档接口，就可以完成一个非常垂直的 Agent。可行性会强很多。

多轮的意义，主要是你可以做 test-time scaling，做很复杂的任务，不只做一次。对话模型往往只说出一轮。Agent 可以做不同的事，就跟人一样。人每天的工作，就是一个多轮使用工具的序列。本质上，你希望把人的这个序列拟合进去；又收集不到这样的数字化数据，就可以用强化学习来构造。说「模拟人」也不太准确。它是一个通用的东西。人也很通用，人是所谓的 Universal Constructor。它的主要目的不是去模拟人，主要目的是通用。这个形式、这个定义本身是通用的，可以完成几乎所有任务。它和人的做法相似，可能只是一个刚好的结果，并不是设计这个系统的目的。设计飞机，是为了做一个交通工具，不是为了像鸟一样飞。Agent 系统更多是为了 general purpose 的智能，和这个目标对齐，而它刚好和人相似。

## 提高通用性：别掉进 benchmark 的盒子

怎么提高通用性，今天仍然很难。Agent 的泛化有一个风险，就是陷入一些 benchmark 的过拟合盒子；而现在又可能缺少很好的 benchmark。这是接下来的挑战。可能的解法是：更多地用 AI 去训练 AI，一定能从多方面缓解这个问题。

现在已经有一部分可以这样做，但希望有更多。很多东西还是靠人设计，链条在走到 Innovator 那一档之前就断了。这很有意思：它其实有可能不是线性的。你要用一些 innovation 的方式，去解决 Agent 的问题。今天 Agent 泛化不够，所以要用 innovation，也就是用 L4 的技术去解决一个 L3 的问题。L1 到 L5 这个定义，有可能真的不是线性的。没有很好的 innovation，没有用 AI 去训练、用 AI 对齐 AI 的方式，Agent 就很难做到特别好的泛化。今天人工定义了一些 task，模型就去拟合那个 task；在别的、你可能看不见的 task 上，表现就可能没那么好。只拟合那些 task、只刷那几个分数，很多时候用户在更 OOD 的场景里，体感就是没那么好。这个领域现在面临的，就是 benchmark 不够用，或者 benchmark 失效，以及 Agent 泛化有问题。

## 数学和代码，也是种瓜得瓜

数学和代码是不是相对容易泛化的领域？其实也没有。如果做强化学习，现在仍然会有一样的问题。强化学习本身的泛化性比 SFT 好，因为过程中有更多 on-policy 的采样——从模型本身去采样，学出来的东西目前看起来更好泛化，而且你有梯度。这两件事会让现有证据看起来泛化更好。但它的泛化仍有限度。假设在某一种类型的数学竞赛上做到九十九分，别的数学问题可能会提升五个点，却很难直接也做到九十九分。如果不把对应的 RL 任务放进去，就很难直接达到那样的泛化。做数学题也仍然一样：它被分布制约。所谓种瓜得瓜，种豆得豆。

现在的整体感觉是，RL 或者 post-training 还是需要有更多 AI 参与，才能摆脱种瓜得瓜。会不会根本摆脱不了、泛化就提高不了？还是回到那句话：问题不可避免，但问题可以被解决。每次往前推进，泛化就会变得更好。它不一定有尽头，你只会有更好的泛化。

## 好的任务和好的环境，是一座隐式的课程

对 Agent 来说，任务和环境非常重要。一种方式是：给定一个模型，设计一些环境，反向去拟合这个模型。如果是一方来做，就可以正向设计工具和环境，让模型在这个环境里提升。很重要的是让这个设计有更好的通用性，能做很多任务，而不是为了某些任务去专门设计工具和环境。设计足够通用的时候，用模型在这个过程中学，而不是反过来拟合模型。这样可能会更好。

一般人会觉得，任务设计上应该做一个足够有挑战的任务，这样才可能逼出本质上的新方法。K2 用的却是一些中等难度的任务。这也是一个爬山过程。不能一上来就让它去证明一个还没有人证明过的数学问题，那样采样成功率会非常非常低。现在感觉比较好的方式是：强化学习如果搭配好的采样策略，本质上是一种隐式的课程学习。所谓 curriculum learning，就是希望它从合适的难度开始学，学完再逐渐提升难度。一上来就学非常难，采样效率很低，基本上学不到什么，算力都会被浪费掉。

挑战在于，今天的很多任务仍然来自人类存量的数据，或人设计的任务，里面 AI native 的部分还比较少。这会带来前面说的泛化问题。

## Coding Agent 是子集，不是终点

Coding Agent 和通用 Agent 是什么关系？Coding 可能是一个比较垂直的，或者说是一个子集。把两个工具用得足够好，就能做大部分事情。最后还是希望不光做 coding。我们训练这个模型，也不是让它只能做 coding，那仍然会有局限。Coding 相当于一个环境，是任务的一个子集，而且可能是很重要的一个子集。它比较好验证，所以比较好学习。但一样有挑战，刚才说的泛化问题，即便是 Coding Agent 也会面临。

代码定义很重要，还因为它代表了数字世界的自动化。今天很多 Agent 的工具集合是固定的。如果你想创建一个新工具，本质上就是写一段或一大段代码。如果想做更好的上下文管理，或者所谓 context engineering，背后对应的也是一个工具，这个工具也可能用代码实现。代码在这里有独特的位置、独特的作用。但不是说做了 Coding Agent 就够了。今天很多不是程序员的人，会用 Claude Code 做他们的任务。你是律师、产品经理，或设计师，也会用它做一些事，因为模型在一定程度上有泛化，不仅只会写代码。

我们还是希望做通用模型。从写代码到操控整个数字世界，AGI 还缺什么？首先，现在这些高频工具的使用也还不够好，能力上还有很大空间。另一方面，现在缺少一些更好的 benchmark 来观测。SWE-bench 现在也可能马上饱和。很多 benchmark 不够好，不够真实地反映实际用户体验。所以高频工具本身有空间；长尾工具，那些完全没见过、完全 OOD 的工具，怎样有更好的泛化，也很重要。

自己最看重、长期能把 Agent 能力抬上去的，是用 innovation 这一层的技术，去提升 Agent 这一层的能力。

Long-term memory 也很重要。很多任务，128K、256K 这种上下文完全解决不了，可能需要百万级别，甚至更多。在这个长度下，脑子还得非常好用。不能只是长，智商还得非常高。这对训练挑战很大。你希望压缩率足够高，模型可能就要足够大，同时又希望它比较强。这两件事天然有冲突，可能需要更好的架构。有些架构在更长的 context 下效果有提升，短 context 却不一定有提升，甚至会下降，于是有很多架构上的平衡问题。这些问题接下来也会逐渐被解决，有一些解法。这是技术上的一个支撑。

现在的 RL 训练方式肯定也有很大提升空间。要训练一个很复杂的 multi-agent 系统，只用端到端 reward 可能不太够。中间的 workflow 怎么产生，能不能摆脱一些人工设计，也会是很有意思的挑战。

## 开源：去年的判断还在，但账要重新算

去年说过，开源会落后于闭源，因为现在的开源方式和以前不一样。以前所有人都可以贡献到开源，开源本身是中性的；现在很多开源贡献没有经过算力验证。必然会有人才聚集和资本密集，市场会整合，领先者不会开得太早，只有落后者才会这么做。今天却把模型开出来了。因为我们还没有做到完全的领先。

有些判断基本上仍然是这样：模型出来之后，社区能贡献一些东西，比如推理侧可以做很多事，可以有更多人使用它。但要贡献到模型本身、让模型本身变得更好，好像还只能由原厂自己来做。如果看 base model，是这样。可如果基于开源模型做很多 post-training，特别是 agentic 的 post-training，有可能会产生新机会。假设你非常想做一个法律相关的 Agent，你是一家创业公司，完全可以基于 K2，在你定制的工具集合上训练出一个 specialized agent，让它在你关注的场景里表现非常好。这样的机会存在。它更多是去赋能下游应用。你很难说把这些东西再变回主模型、变成 base model 的提升。这目前还是很难。这个问题可以动态地观察，看开源和闭源之间的关系怎么变。

会长期选择开源吗？这是希望长期去做的事。但不一定只做开源，会希望跟社区分享，比如前面说的技术 know-how。这可以加速技术继续往上走。大家可以不完全只是竞争，也可以有一些合作；甚至开源的公司会形成一个生态，把技术往下推进，把这座雪山爬得更好。Reach to the top，也不一定所有东西都开源。假设和某些公司有合作，不一定所有东西都要开出来，但会希望持续开放一些好的技术。

这是技术体系的信仰，还是市场博弈？客观地说，都有。过去两年的趋势比较明确：市场会逐渐更集中、更聚焦、更收敛。一开始可能有几百家，后来几十家，再到几家。几家可能是最终比较稳定的数目，现在看起来是大概率的事。我们会持续地开，但并不是所有东西一定都完全开。选择性开放，很多要动态观察。同时肯定希望长期分享更多技术。

为什么中国公司都开源了？也不是都开，自己以前就没开。客观地说，还是有市场博弈的因素。对社区来说这是好事，开源的可以互相借鉴，可以加速做得更好。这是一个很好的方式。

## 有概率的非共识

去年常说一个词：有概率的非共识。今天的非共识，就是前面讲的几件接下来比较重要的事。怎么提升 Agent 的泛化，仍然非常重要，希望在这上面做出一些新东西。也包括去做优化器。至少在我们做出来之前，应该没有人在做这个，所以它做成了一个非共识——以前所有人都会用 Adam。它也比较重要，因为对 token efficiency 的提升确实很大，使我们现在可以有一个比较好的 base model。有了这个 base model，后面就可以有更多 post-training，把上限和性能压榨出来。

## 模型即产品，这句话没有变

做了很长时间 Kimi 之后，看 AI 时代的产品和移动互联网产品有什么不一样——移动互联网没有做过，只能说 AI 的产品。以前很喜欢说「模型即产品」。这句话现在还是没有变化。假设你在做一个 Agent 产品，做的时候就要把模型、工具和 context 结合起来。你会发现，训练模型的时候，基本上已经要把这一套全部搭好，否则没有办法训。所以模型训完，产品已经做完。上面再做一些交互，肯定也有很大价值，但那可能是最后锦上添花的一步。模型的性能在训练过程中打磨好了，和这些工具、环境已经有非常好的适配。它是在训练之中完成的。训练好了，产品就基本上做差不多了。

去年说过，开发方式会演变成做一个巨大的系统，像二十一世纪初 Google 做的信息检索系统。今天对 AI 时代这个巨大系统，可以有更多想象。以前的搜索引擎、以前的推荐引擎，都适配各自的时代。现在系统的复杂性在于，你想让模型变得通用，通用会带来很多复杂性。一方面可以认为它变简单了，另一方面也可以认为它变复杂了。简单在于，你只要把所有东西放在同一个模型里，不需要维护那么多模型，不需要搞一堆 routing 策略。从概念上、从一些工程实现上，它变简单了。复杂在于，你如果希望它很通用，就希望这个模型在各种场景下都可以工作。做 Agent 模型，不希望它只在你的工具集下能工作，而希望别人拿去，在别的工具集、甚至你没见过的工具、不同的定义和实现方式上，都能工作。这个要求很高。

Agent 里现在可能有几种不同类型的任务。Coding Agent、Search Agent，或者其他 Agent，要放进同一个通用模型。它们可能会打架。工具定义不一样，或者数据的 pattern 不一样，把它做成通用模型的过程，有很多技术挑战。如果不做成通用模型呢？泛化还会不会那么好？你就只能做一件事情。特别是现在，Agent 要很多步才能完成任务。即便程序员，也不只是写代码；写代码里面，也不只是做一件事。你要做真正可用的东西，随着步数变多，对通用性的要求会更高。系统复杂性主要体现在：训练这个模型的过程中，要让它足够通用，而不是拟合到某些单点能力上。单点上，benchmark 分数可以看起来很好，实际上通用性可能不够。这是现在这个系统里，自己能观察到的比较大的挑战。

还有一个例子。你想往模型里加多模态能力，就要让多模态不要损伤它的脑子。能不损伤，已经很好了。多模态能力本身要做好也不容易，里面有很多工作。你还希望在多模态模式下，和文本模式共用一个脑子，把文本里的智商激发出来，而不是进入另外一部分参数，把原来在文本里学到的东西完全丢掉。假设 MoE 里有二十个 expert，专门在做多模态，你可能不希望这种情况出现。那样出来的多模态，是个傻子。我们希望它是个聪明的多模态。作为一个通用模型，就会面临这样的挑战：各种模态、各种任务类型，还有 Agent、Reasoning、Chat，要全部合到一起。而且现在不光是 SFT，还要做 RL。上了 RL 之后，挑战会进一步加重。相比之下，只做通用的预训练相对比较好做，把所有文本放在一起，基本上不会有太多问题。越到 post-train 后期，越到 RL，这个问题越严重。这就是它的系统复杂性。

## 新的节点在数据中心里，交互则跟着能力变

搜索引擎构建在 PC 互联网上，推荐引擎构建在手机、移动互联网上。新的节点在哪里？它肯定会跑在很多数据中心里，也就是常说的 AI factory。但肯定还会有很多终端。终端有些可以复用现在的，有些可能会诞生新的交互方式。

Chat 就是一种。两年前看，人和机器这样对话，是新的交互方式，因为以前没有。现在 Agent 也有很多新的交互：你让它一步步执行一个任务，又可以看中间结果。这其实也是一种交互。接下来还会有更多。有了 multi-agent，交互方式会怎么样？可能会随着能力的边界变化。Coding 一开始有 Copilot，Copilot 之后有 Cursor，之后有 Claude Code。每一代交互都在变，而且交互是随着模型变的。基本上，新一代模型能力提升很多，交互就可以改了。你不再需要人一个一个点接受修改，而是可以多步执行一个 agent coding 任务，交互就更方便。今天 Claude Code 的交互也不是终极形态，因为模型还会提升，提升之后交互会持续变化。

## 数据墙是事实，数据飞轮还没转起来

今天 scaling law 有没有放缓？数据墙是一个客观事实。要突破数据墙，就要提高 token efficiency。我们会去做提高 token efficiency 的事，就是因为数据墙存在。同时要把更多 compute scale 到 RL 上，scale 到各种各样的 RL 任务上。somehow，我们现在观察到，模型变好的速度并没有在减少，甚至是在加速。

为什么 AI 产品都还没有形成数据飞轮？因为基于算力的 scaling 太强大了。你先 scaling，再用 scaling 做 RL。RL 的 scaling 效率又比预训练高很多，因为它是 on-policy、带 advantage 的训练，scaling 效率更高。当 scaling 效率很高，直接 scale compute、scale FLOPs 带来的提升非常非常大，其他东西带来的提升就显得很小。这是一方面。

另一方面，所谓数据飞轮很依赖外界环境的 feedback，而且不希望这个 feedback 有太多噪声。现在信号这件事还没有做得非常好。噪声一大，学习就受影响。大模型学习对噪声比较敏感，和传统推荐系统有点不太一样。现在看起来，基于 FLOPs 的 scaling 更有效。这个平衡什么时候发生变化，不好说。也有可能通过新的交互，让收集到的信号噪声减少。但这需要创造一种新交互，而且交互又要适配模型能力的发展。交互不能超越模型能力，应该在模型能力范围内设计一个好的交互。这值得尝试。只是今天看来，去 scale FLOPs 那个维度，或者说提升它的学习效率，确定性更高，而且看起来更有效。

如果说用户数据无法提供模型的智能，那今天是不是就没必要做 ToC，一门心思提升智能就好？这要看怎么看。你可能没有办法直接把用户反馈拿去训练。但有一定用户量的好处是，你知道整体需求的分布是什么样，大概知道哪些用得好、哪些用得不好，再把这个东西抽象成一些 evaluation，去优化模型。模型完全没有人用，你可能都不知道往哪里优化。

另外要看用户的商业价值。现在其实又到了一个新的分水岭：用户有可能产生商业价值。看 OpenAI，其用户产生的商业价值很大，可能占了营收里相当大的比例。特别是现在有很多 Agent 产品，能端到端产生很多价值。所以也要看是什么用户。如果只是普通地闲聊、问一下天气，不一定有那么大的商业价值；如果是很多 Agent 的专业用户，他本身就已经是一个很好的生产力价值。这件事就不完全一样了。

产品有什么新想法？更多还是想模型怎么做。模型训好了，产品就已经基本上做差不多了。模型即产品今天还是成立的，我们还会沿着这个方式做下去。

有人会说，你们是要从做「中国的 OpenAI」，变成想做「中国的 Anthropic」，有这样的转换吗？很难这样定义。中美不太一样，今天更多还是得站在全球视角思考。做「中国的什么什么」，本身不一定非常成立。其实简单一点：我们希望继续爬山，做时间的朋友，和社区一起加速技术推进。这是我们想做的事。

## 商业模式已经看得到，但第一优先仍是效果

API 是不是好生意？现在明确的商业模式，一个是 API，一个是一方产品。这两个可能都会做一些尝试。今天最主要的，还是继续把模型做得更好。这可能是首要目标。在把模型做更好的过程中，如果领先了，确实会有商业化空间。今天整体市场规模涨得也很快。头部公司有几十亿、上百亿美元的 ARR，而且在快速增长，可能每一两个季度就能翻两三倍。我们会动态观察，做一些尝试。但最主要还是：如果模型真能做到比如 Opus 的水平，甚至更好，空间肯定会更大。所以会花更多时间把效果做得更好。

有用户说很喜欢 Kimi，但很担心 Kimi 赚不到钱。能不能挣到钱？还是先投资。能不能赚到钱，取决于模型效果怎么样。现在觉得，这个市场其实已经是一个被商业验证的市场，而且在快速增长。所以还是专注，把技术做得更好。剩下的东西，确定性反而更高。

K2 火了，心情有什么变化？也没有，还好。这仍然是一个漫长的旅程，要持续做下一代模型。还是回到刻在石头上的那两句：会产生新的问题，然后去解决它。这可能是最有意思的部分。

## 意料之中的是困难，意料之外的是新问题长什么样

这段创业里，完全意料之外的是什么？还好。基本上所有的困难，我们都有预料，只是具体是什么困难，不一样。最有意思的点是，你永远不知道会产生什么新的技术问题，这些新问题会怎样被解决。这是你基本上很难预测的。如果能预测，它就不是那么创新。你会永远遇到新的问题。

现在的生活，是睡得比较晚，而且不太一样，可能每天不一样。但也还好，花很多时间看怎么把模型训练得更好。时间主要投入在模型训练上。模型训练是个很抽象的概念，里面很重要的一块，是技术战略。这可能是公司战略里最重要的一部分：下一步到底哪些要做，哪些不要做。技术空间很大，总是要选一些东西重点做。

去年选择了什么？很多东西上的 bet 还是有效的，而且比较早。比如做 long CoT，反应比较快；去做 Muon 优化器；去做更大规模的训练；去做一个可能是第一个开放出来的 Agent 模型。这些都是一些技术 bet，或者技术决策。这个东西基本上至少会决定五六成的公司走向。

但要做很好的决策，还是需要很多证据支撑。还得做很多实验，了解很多具体实验结果：这个东西是什么样，那个怎么样，接下来可能会怎么样发展。不能拍脑袋，还是得知道更多信息。这会花很多时间。第二块才是具体的技术。

这些选择里最纠结、花时间思考最长的，是接下来要做什么、不做什么。关键其实是一个收集数据的过程：做实验，看实验是不是扎实，再结合你对技术的理解去判断。很多时候，只要数据足够充分，判断也是比较显然的。接下来也在想，也在做一些实验，还是有很多东西可以做。至少现在 K2 的性能潜力还没有被完全压榨出来，之前放出来的更接近一个 base model。接下来可以加更多 post-training 的 FLOPs，上限应该还会比现在高很多。肯定还会做下一代模型，base model 应该可以有更多提升。具体怎么做，现在也通过一些实验来决策。

也会加多模态。多模态是比较确定的。多模态只要不干扰智能就已经很好了——多模态能力本身要做好也不容易。怎么让它借鉴文本的「脑智」，而不是自己单开一个脑子，是真正要做的工作。

## 眼下的里程碑：泛化，和又长又聪明

技术上下一个重要的里程碑，泛化未必是唯一的一个，但 Agent 泛化这件事情可能是最重要的。今天它是一个没有完全被解决的问题。我们解决了一些，know-how 写在论文里：你可以尽可能构造更多样的数据。还不只是这个。还是尽量避免一种情况——你用强化学习，结果只过拟合到了几个任务上。benchmark 现在比较局限，优化 benchmark 就会导致 RL 任务坍缩到几个单点上。这是我们不希望的。你会发现，在你没有观测的东西上，它可能掉得非常多。现在也希望想更多办法去解决，这会很重要。

Long context 也肯定会继续看怎么做：在智商很高的情况下，还能有更长的 context。现在很多 long context 的架构还是会影响智商。我们不希望它影响智商。比如做纯粹的 Linear Attention，它可能就会影响智商，因为这个架构会有一些 bias，在一些场景下效果没有那么好。这在一定程度上也是可以被解决的问题。

## 一方产品有整合优势，垂直工具仍有窗口

模型公司和做 Agent 产品的公司，长期的关系和边界在哪里？今天没有明确答案。今天看起来，一方产品有个好处，是可以做垂直整合。可以把模型放在里面训练，模型和工具融为一体，不是分开做、再去逆向工程。但 Agent 的空间非常多，一方产品不一定做得过来。如果能找到一些空间——工具的实现需要非常多的领域 know-how，或者你的 evaluation 是一方产品根本不会考虑、考虑不过来的——那就有机会。有 K2 这样的开源模型，大家可以在上面微调，更容易产生 specialized agent、垂直 agent。这种可能性一定程度上会存在。

不管通用到什么程度，总还有一些工具要做。所以你不一定非要去做那个模型，而是把工具做得非常好。如果这个工具做得太通用，就可能和一方产品 overlap，交集比较大，那还是垂直整合优势更大。如果你的工具是专门针对一个东西做的，甚至是别人做不了的——比如你掌握了一些线下服务的入口，下单或成交这个工具是别人根本做不出来的——那就有可能产生独特价值。

也存在另外一种可能性。当一方产品，或者说通用 Agent 的流量和商业模式足够成熟之后，很多本来垄断的专有工具也会愿意接进来，因为整体商业化效率会更高。但商业化效率的提升需要时间。在这个时间窗口内，专有 Agent 也会有空间。最终通用之所以能工作，是因为它整体的商业化效率更高。今天甚至包括很多内容平台，最终有可能把内容接到通用 Agent 里面，商业化效率比今天更高。这是有可能的，但可能要花很长时间。

像 Manus 这样的公司，是客户还是竞争对手？生态链上还很早期，很难判断。产品本身也会演进。短期内，合作关系可能大于竞争。但未来确实会演进。有点像 Claude 和 Cursor 的关系，Cursor 可能也要动态变化，在产品策略上做动态调整。一方面，能不能有一些模型能力——技术研发的曲线还是很陡峭。另一方面，能不能有一些别人做不到的工具或环境。这些都是现在没有办法直接回答的问题。只能说，现在看起来，一方的整合优势应该是存在的。

## 名字叫 K2，是因为难，不是因为到顶

K2 本来就是一座可能是世界上最难攀登的山峰，刚好名字有点重合。是有意选的。它也刚好是 K2。但希望大家首先知道，它不是终点，因为它不是最高的山峰，它可能是最难的。现在有很多范式转变，从对话到 Agent，base model 的 scale 也进一步变大，它本身肯定存在难度。所以刚好有点关联。

结果有没有超出预期？差不多。模型训练得怎么样，其实在过程中就已经知道了，并不会有一些惊喜或惊讶。过程中有没有 aha moment？也还好，因为很多东西可以被预测。更重要的是预测能力。训练一次模型，一是需要周期，二是有成本。所以希望在早期尽可能把所有能预测的都预测到。唯一没有预测到的，就是刚才说的 Max Logit。那个确实没办法，小规模预测不了。其他的，都希望尽可能预测好。所有东西都在验证清楚的情况下再 scale，scale 的成功率就比较高。

## 只做下一个 token，模型不会自己变聪明

有人谈到 next token prediction 的本质缺陷：随着模型规模扩大，对话能力、知识量和情商都在变强，但推理能力、尤其数学的表现是先上升、后平缓，再扩大反而下降。用更大的模型做数学，倾向于跳步，不老实。这被看成 next token prediction 的本质缺陷。

所以要搭配强化学习的 scaling。确实，如果今天不做强化学习，这个模型很难说很聪明，数学题也不一定做得非常好。但更大的 base，在强化学习上的上限还是会更高，因为它的知识更多。本质上是去激活一种推理范式，让它把知识解锁出来。上限更高，但你要搭配一个 RL 去激活。

## 世界模型、GPT-10，和还没做完的评测

世界模型怎么看？有一种说法是，做世界模型是造世界，做 Agent 是造人。最后就像前面说的，用 AI 训练 AI，有点这个意思。你有一个很好的世界模型，就可以模拟这些东西。那就是用 AI 训练 AI 的方式，它的泛化会有很多空间。这有可能是通往更好泛化的一种可能性。

有投资人说，第一次见面就开始讲 GPT-10 可能长什么样，印象很深，因为讲的不是 GPT-4、GPT-5，而是 GPT-10。今天其实已经实现了之前预想的很多东西，比如真的能完成几个小时的任务。发展还是很快。整体上，就是逐渐见到更多的 variation，再去突破泛化。这个方向相对来说还是比较明确的。

在 evaluation 上，也在探索。刚才说的世界模型，可以认为是这里面的一部分。怎么实现，现在还需要更多实验。

## 管一个做创新的团队，也很像强化学习

过去一年对组织有没有新想法？最近在想，有几个东西好像联系在一起。我们做科研、创造新知识的过程，很像一个强化学习的过程。有一种理论叫经验主义，说人的新知识是从经验来的。后来很多观点认为不是这样。人类在地球上已经存在非常非常多年，可三四百年之前，没有人说地球是个球。它一直在经验里，你并不知道事实是什么样。经验并不能直接给你知识。是你提出了猜想：观察到一些东西，然后说，我认为它可能是圆的，再想各种办法验证。训练神经网络也一样。你可能观察到几十万个内核指标，有些不太对。直接观测并不能给你新知识。你提出一个猜想：它为什么会这样？再设计一些实验去验证。比较好的科研方式，可能都是这样。

这几件事的想法是相通的。管理一个团队，也是这种方法：要用 RL 的方式去管理，而不是用 SFT。这是 Tim 天天在讲的。当然，现在好的技术也会告诉你，做 RL 的时候其实也希望加一部分 SFT。SFT 是很好的先验，就是所谓的 PTX loss。你不希望模型飞太远。但你又要管住自己的手，不能 SFT 太多。SFT 太多，这些同学就会失去主观能动性，没有办法创新。这个点现在也在做一些实践，看起来有一些效果。核心是掌握 SFT 和 RL 的平衡。

SFT 是直接告诉他：这个东西应该这样、这样、这样做。RL 是由上而下，给他一个奖励：做成这样，可能是好的。更多时候，它反映在目标上。这两个东西需要平衡，可能以 RL 为主，通过一部分 SFT 防止它飞太远。你还是要有一些先验去控制，防止它遗忘掉一些东西。这些在某种程度上是连在一起的。创新好像是一个很本质的东西。组织在做创新，本质上也是一个 RL。

但在 RL 过程中，定奖励、定指标，并不是非常简单的事。如果最后只说，我就是要把所有 benchmark 做很高，就可能出现很多过拟合。所有人都会不择手段把那个分弄上去，弄完发现模型好像并没有变好。所以奖励的定义很重要。奖励的定义也需要你很了解具体细节是怎么运作的，不然就会出现 reward hacking。

怎么定义 reward，是一个很重要的课题。想法还是：建立更多观测指标，尽可能不要过拟合。这样才有更好的泛化，不会被 hack。用 RL 管理团队，最大的问题就是容易被 hack。大家 hack 那个 reward，看起来各种结果都很好，实际上并没有达到你最终想要的。这是它的风险。用 SFT 管理团队的风险，则是大家失去创造力。最后是这几个东西一定程度的平衡。这个也在学习。今天肯定不是做到很完美的情况，要逐渐去学习和理解。

## 低点会有，复杂多半是后加的

过去有没有很低落的时刻？也还好。更多是有些东西会 work，有些东西不 work；解决了一些问题，又有新问题产生。只要你觉得这东西有意思，就会一直想继续做下去。

对 CEO 这个身份，最新的理解就是：怎么把握 RL 和 SFT，还有防止 hacking 之间的平衡。

过去一年，Kimi 也是波峰波谷，来回震荡。在其中的心态是什么，需不需要平衡？心态就是做时间的朋友。真实的心态不会这么简单。你会有高点和低点。可能很重要的，还是你喜欢做这件事，想把它做好，所以也不用想别的，就想怎么把它做好。好像也比较简单。很多复杂的事情都是人为强行加上去的，实际上并没有那么复杂。

对人性有没有更多理解？这个也还是需要时间打磨。不敢说有那么深入。你只能在自己的故事里面不断感受：自己到底是什么样的一个人，为什么要做这件事。可能就是不断思考这些问题。

是一个什么样的人，为什么做这件事？就是觉得有意思。什么有意思？做实验有意思，做科研有意思，做 AI 有意思。寻找真相的过程有意思：不断发现新问题，再解决它。

那也可以解决别的问题，为什么是这个问题？因为这个问题很重要。AI 很重要。这个问题也问过 Kimi。Kimi 说，这个东西是人类文明的放大器。觉得很有道理。又回到 *The Beginning of Infinity*。从启蒙运动到现在，人类一直在找新的方法突破知识的边界。可能下一个突破边界的，确实得靠 AI，因为它是一个巨大的杠杆。今天在任何一个前沿学科，你要花几十年、二三十年，才能学到最前沿的知识，AI 可能一夜之间就能学会，然后往下做新的突破。AI 会成为一个 meta science。这也是很重要的，人类文明的放大器。

## 风险存在，放弃它就是放弃上限

它有可能摧毁人类文明吗？这一点上，风险肯定不能说不存在。但我们可以做很多事情：更安全的对齐，更好的社会机制。当它能做一些事情的时候，其实很有可能会创造出新的工作。我们需要一些方法完成这个过渡。最终，技术还是会往前走。

正好问过 Kimi 这个问题。它的意思是：虽然有这样的风险，但我们可能不能放弃这件事。放弃，就等于放弃了人类文明的上限，你不知道上限能做到什么样。有一点因噎废食。但得承认，我们得做很多事。今天看到的很多 AI 能力，是有点让人震惊的，半年前根本想不到能到这样的程度。需要做的事情很多。同时，人的独特价值在这个过程中还会持续存在。人的体验、人的情感，没有办法被 AI 替代。所以可能会有不同的活法，而且希望是能活得更好。

什么样的活法？以前觉得，人的一生可能有几种不同的意义：创造、体验和爱。每个人不一样，这是对我来说的。创造里面，很大一部分也许有可能 AI 可以做。我还是很享受这个过程。但不得不承认，有一天很多创造性的工作可能由 AI 去做。后两条，可能仍然会是以人为中心的。

如果创造被拿走，生产力其实也被拿走了。这无所谓，因为人可以享受生产的结果——如果我们有一个好的机制。还是需要改变社会的机制。它也是一个缓慢的过程，不会一两年做完，可能要一二十年，逐渐调整。

会频繁跟 Kimi 聊天吗？当然，因为要测试模型。会聊一些很深刻的话题，或者很自我的话题吗？有时候会。除了刚才那些，也还有一些是工作自身的问题。

## 往上爬，成功概率就在变大

相比一年前，今天 Kimi 的成功概率是变大了，还是失败概率变大了？成功概率变大了。只要还在往上爬，成功概率都会变大，因为会有一些人不再继续爬。但也会有掉下去的恐惧。恐惧很多时候，更多还是让你关注当前这一步能做什么。有时候想这个问题更重要。

过去有没有走弯路？肯定有。这个过程中会有很多决策，有些是技术决策，有些是业务决策。很重要的是，一个公司在这个过程中逐渐具备调整的能力。知识创造也是这样。你不可能创造出来的知识全都是对的。有的东西是错的，它在一定时间内可能是对的，在另一段时间内可能是错的。错了之后，你知道去做调整。牛顿做的很多东西，当时是最好的理论，但不是完美的理论，它有错误，在一些场景下完全就是错误的理论。万有引力需要别的解释，需要相对论，通过时空的扭曲去解释。

组织的进化、一个公司的发展，是一个动态过程。任何中间点，在某些时间是对的，在有些时间可能是错的。这也是 Kimi 告诉我的：任何中间状态都会成为被批评的对象。你总是会有这个时代的局限性。更重要的是，在这个过程中怎么走。一是投入一些可能一定不变的东西，比如人才和技术的积累；另一些是去适应和调整，针对反馈信号，或者环境的状态变化，做一些决策调整。这两件事很重要。

## 投流不是主变量，智能才是

做 AI 产品和做互联网产品是不是完全不一样？互联网产品会通过投流扩大地域、扩大市场规模。AI 产品很不一样：能力提高了，benchmark 提高了，它自然就可以获客；可获了客，又不知道用来干嘛。这个怎么平衡？

它有时候也不一定那么自然，取决于两个变量哪个大。如果你处在技术快速发展的阶段，很难说通过投流去赢得这场战争。投流很难成为打赢的方式，它更多是辅助手段。辅助手段和主要手段之间到底什么配比，可能需要动态调整，也取决于你现在的商业化进展，或者说 PMF 到底有多强。不同时间点会有不同策略。甚至也许再过两年，你会发现它又是一个好策略。我们用更开放的心态看。但在每个时间点，最重要的是看哪个是最大的变量。今天最大的变量依然是智能。还是爬山。

## 少做情绪化的决策

聊到各种情绪，回答往往是「还好」。最近一次，或者最近两次，真正嗨起来是什么情境？希望做到不以物喜，不以己悲。这也很难做到。但要避免一些情绪化的决策。人多少肯定会情绪化，因为你是一个人。最终落实到决策和执行上，还是要更理性一点。

过去这一年最大的成长，是认识到一点：问题是不可避免的，它会一直存在。持续解决新问题，是最重要的，可能也是最有意思的。这是心态上的一个变化。它可能会改变很多做事情的方式。这是一种比较正面的方式。

今天会不会比一年前更兴奋？会。有两个因素。一方面，更适应这种状态，兴奋值会减少。另一方面，AI 进展很快，能力又提升了，兴奋值又增加。所以基本上可能维持在一个比较稳定的水平。
