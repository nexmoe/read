# AI时代不该再把挑错、对齐上下文和签字担责捆成一种逐行review，而要拆开：机器做廉价复查，人定义正确、踩刹车并最终背锅。
## Chapters
- **逐行审会被PR淹没，不读又得背锅** — AI写得比人读得快，代码表面工整、自审后更难挑错，有效的人工review反而更费时；“不读、大不了回滚”技术上说得通，出事和绩效扣分仍由人承担。
- **先把code review拆成三件事** — 过去捆在一起的是挑错、核对架构与业务是否对齐、以及签下“ship it”；三种死结分别来自吞吐太大、真正的上下文不在diff里、责任仍在人身上，所以不能幻想一种更强的review一次解决。
- **挑错交给几乎免费的机器double check** — 经理不会把下属的活重做一遍，否则自己成瓶颈，但机器重做很便宜；做法是AB赛马、提PR前用全新上下文的子Agent复查，再让多组Agent从不同视角找问题并交叉投票，人只处理对不上的地方。
- **给人机复查设三轮上限，人负责踩刹车** — 模型会互相挑刺、加guardrail、把小项目的范围撑到不收敛；Anthropic最多让机器改三轮，仍不收敛就停下来重做设计。人不再逐行替机器找错，而是制止没完没了的scope expansion，并设计筛选机制。
- **diff里没有的上下文必须cross check** — 某次后台会话超时改动过了CI和AI审查，上线后企业导出任务中断；根因是六周前的企业定制打破了“后台任务都在常规会话里跑完”的隐含假设，而那次改动不在本次diff里，把代码读一百遍也看不见。
- **把部落知识写成文档，核对边界才能外推** — 对得上问题靠的是数量级嗅觉、产品历史和上下游变动；这些若只在人脑子、私信或无记录会议里，AI读不到。人的cross check一旦落成文字，下次就变成机器可重复的double check，人盯细节的边界就会不断外移。
- **签字背锅推不给AI，批准只认这一次commit** — 道歉、赔钱、降职都不能让Agent顶上。Anthropic定了三条：Agent不算Approver，人的批准只对特定commit有效，指挥写代码的人必须在签名名单上；签名从“逐行读过没毛病”变成“意图、假设和设计已核对”。
- **Scion从高层看意图，实现交给测试** — 给Agent用的高吞吐Git不逐行读实现，只看改动想干什么、是否符合惯例、会不会碰到奇怪corner case；底层对不对交给测试和仿真。
- **每天三万变更要分级，并用快速回滚换少审** — 纯文档、功能开关等低风险在测试通过且作者可信时可免签；常规业务逻辑和系统提示词一人签；常挂的核心路径和难恢复的关键配置两人签。Scion先合并，挂了再用二分找到改动撤回。
- **四个月的结果，以及现在就能做的四件事** — 这套工序跑四个月后，Claude Code仓库合并的PR多了一倍还不止，回滚比例反降百分之四十。不必上未开源的Scion：先写验收标准、换全新上下文或双AI赛马、积累自己的sniff test、保证代码配置和报表都能快速回滚。
- **边界可以外推，三样责任始终留在人身上** — 一次上下文核对写成文档，下次机器就能用；但动手前定义什么叫正确、交付时签上名字背锅、把还没写下的规则和直觉补成文字，这三件推不走。
